# Обслуживание сервера: обновление, очистка, лимит трафика

Редакция от 8 ноября 2026. Команды выполняются на DE-сервере из папки
`/root/vpn-src`. Сначала всегда отчёт без изменений, потом изменение.

## Обновление сервера

Одна команда обновляет пакеты системы (Docker тоже), базовые образы, бота и
сайт и проверяет базы данных.

```bash
cd /root/vpn-src
bash scripts/server_update.sh            # отчёт: меняет только списки пакетов
bash scripts/server_update.sh --apply    # обновление; в конце SERVER_UPDATE_OK
```

Запускайте раз в месяц в тихий час. Что делает `--apply` (при ошибке
останавливается на этом шаге):

1. **Копии.** База Marzban копируется без остановки и проверяется на
   целостность. Копируются также настройки Marzban (`/opt/marzban`,
   `xray_config.json`), `.env` бота и `secrets`. Всё складывается в
   `/root/server-backups`, доступ только у root, хранятся три последние копии.
2. **Пакеты системы.** Пакеты обновляются, ни один не удаляется, изменённые
   вами файлы настроек сохраняются. Прежние версии пакетов Docker записываются,
   а в выводе есть готовая команда, чтобы откатить версию. Если обновляется
   Docker, контейнеры перезапускаются, и связь у клиентов прерывается примерно
   на минуту. Скрипт ждёт, пока снова заработают все контейнеры, которые
   работали до обновления.
3. **Бот и сайт.** Сначала скачиваются свежие базовые образы с исправлениями
   безопасности. Затем бот и сайт пересобираются через `update_bot.sh` и
   `update_web.sh`. Каждый из них сохраняет прежний образ и сам возвращается на
   него, если новый не прошёл проверку.
4. **Очистка и проверка.** Запускается `server_cleanup.sh --apply` (см. ниже).
   `--doctor` выполняется до и после обновления.

Не трогается: версия и настройки Marzban, Xray, его правила и geo-файлы,
файрвол, SSH. Новое ядро начинает работать только после перезагрузки. Если она
нужна, отчёт пишет `REBOOT NEEDED`: перезагрузите сервер командой `reboot` в
тихий час, контейнеры поднимутся сами.

### Если что-то пошло не так

- `SERVER_UPDATE_STOPPED: …` — шаг не удался. Всё до него сделано, дальше
  ничего не начато. Пришлите вывод.
- `SERVER_UPDATE_DONE_WITH_NEW_PROBLEMS` — обновление прошло, но `--doctor`
  нашёл новые проблемы. Строки `FAIL` в выводе говорят, что не так. Прежние
  образы бота и сайта сохранены: `docker images node-rental-bot` и
  `docker images node-rental-web`.
- Docker после обновления работает не так: выполните команду из строки
  `downgrade if ever needed`.
- База Marzban повреждена: остановите Marzban (`marzban down`), замените
  `/var/lib/marzban/db.sqlite3` последней копией из
  `/root/server-backups/marzban-db-*.sqlite3` и запустите (`marzban up`).

## Очистка

```bash
bash scripts/server_cleanup.sh            # отчёт: ничего не удаляет
bash scripts/server_cleanup.sh --apply    # удаляет то, что в отчёте помечено would remove
```

Удаляется само:
- старые образы бота и сайта (кроме двух последних образов для отката),
  неиспользуемые слои и кэш сборки старше недели;
- другие версии образов работающих сервисов, которые не использует ни один
  контейнер (при необходимости они скачаются снова);
- старые копии баз и `.env` после обновлений, старые ключи;
- журнал системы старше 14 дней, кэш apt;
- старые ядра — только те, что выбрал бы сам apt; работающее ядро не трогается;
- логи контейнеров больше 200 МБ: файл лога очищается, контейнер продолжает
  работать;
- технические строки базы бота (перед этим делается проверенная копия).

Только показывается, решение за вами (рядом с каждым пунктом есть команда):
- образы, которые не использует ни один контейнер;
- остановленные контейнеры;
- тома Docker без контейнера (данные в них пропадут при удалении);
- большие архивы и логи в `/root`, которые не менялись две недели.

## Базы Xray: geo-файлы и реестр

Автоматически они не обновляются. Если в новом файле не окажется категории,
на которую ссылается действующий конфиг, Xray не запустится и отключатся все
клиенты. Порядок обновления описан в `docs/SECURITY_POLICY.md`, раздел
«Обновление и подготовка к включению». Отчёт `server_update.sh` показывает,
сколько дней назад обновлялись `geosite.dat` и `geoip.dat`.

## Лимит трафика сервера

Тариф хостинга включает 5 ТБ трафика в месяц. Бот следит за ним сам:

- **Учёт.** Каждые несколько минут к трафику текущих суток добавляется трафик
  всех клиентов (VLESS и AmneziaWG). В базе хранится одна строка в сутки, без
  данных о клиентах.
- **Прогноз.** Раз в час бот строит прогноз на расчётный период хостинга.
  Модель — экспоненциальное сглаживание с затухающим трендом. Её параметры
  подбираются по истории до 8 недель так, чтобы точнее всего предсказывать
  следующие сутки. По разбросу прошлых ошибок считается верхняя граница, ниже
  которой расход окажется с вероятностью 90%. Если истории меньше недели,
  прогноз строится по среднему за сутки, а в первые часы — по сегодняшнему
  темпу. Дни периода, когда бот ещё не работал, заполняются оценкой модели.
- **Предупреждения владельцу.** Израсходовано 80%, 90% или 100% лимита;
  прогноз 90% или выше; прогноз превышения с датой, когда лимит закончится.
  Каждое приходит один раз за период.
- **Пауза пробного доступа (включается отдельно).** При 90% израсходованного
  новые пробные доступы приостанавливаются до начала следующего периода.
  Платные подписки работают как обычно. По умолчанию пауза выключена: п. 1.6
  оферты обещает пробный период после акцепта, поэтому сначала нужно дополнить
  оферту (см. ниже).
- **Команда `/traffic`.** Показывает расход, прогноз, темп, средний расход
  клиента и на сколько клиентов рассчитан лимит.

Настройки меняются через `update_bot.sh --set`:

| Ключ | По умолчанию | Значение |
|---|---|---|
| `SERVER_TRAFFIC_LIMIT_GB` | `5000` | Трафик тарифа хостинга в ГБ (1 ТБ = 1000 ГБ); `0` выключает учёт |
| `SERVER_TRAFFIC_COUNTS` | `both` | Что считает провайдер: `both` — входящий и исходящий, `out` — только исходящий, `in` — только входящий |
| `SERVER_TRAFFIC_RESET_DAY` | `1` | День месяца, когда провайдер обнуляет счётчик (1–28) |
| `SERVER_TRAFFIC_PAUSE_TRIALS` | `false` | `true` — приостанавливать новые пробные доступы при 90% лимита |

**Почему это оценка.** Бот видит трафик клиентов, а провайдер считает трафик
сетевой карты сервера. Каждый байт, который скачивает клиент, проходит через
карту дважды: из интернета на сервер и с сервера к клиенту. К этому добавляется
около 5% служебных данных. Поэтому при учёте обоих направлений бот умножает
трафик клиентов на 2,1, а при учёте одного — на 1,05.

**Что сделать один раз.** Узнайте в описании тарифа или в поддержке хостинга,
какой трафик учитывается. Если только исходящий:

```bash
bash scripts/update_bot.sh --set SERVER_TRAFFIC_COUNTS=out
```

Раз в месяц сверяйте `/traffic` с панелью хостинга и с `vnstat -m` (его ставит
`server_update.sh --apply`). Если цифры заметно расходятся, напишите — уточним
множитель.

**Как включить паузу пробного доступа.** Сначала опубликуйте новую редакцию
оферты, где в конце п. 1.6 добавлено:

> Исполнитель вправе временно не предоставлять новые Пробные периоды, если
> Узел близок к исчерпанию месячного объёма трафика, предоставленного
> хостинг-провайдером. Уже начатые Пробные периоды не прерываются.

Затем:

```bash
bash scripts/update_bot.sh --set SERVER_TRAFFIC_PAUSE_TRIALS=true
```

**Ограничения.** В учёт не входит собственный трафик сервера: обновления,
скачивание образов, резервные копии. Обычно это единицы гигабайт в месяц.
Если серверов станет несколько, прогноз сложит трафик всех серверов вместе.
