# Вход на сайт по коду на почту

Актуально на 14 ноября 2026 года.

## Зачем

Замеры с мобильной сети (`DEPLOYMENT_STATE.md`, 14 ноября) показали: сайт и точки входа
открываются, а Telegram нет, ни один из четырёх адресов. Вход на сайт был только через
виджет Telegram, поэтому человек без работающего VPN не мог ни купить подписку, ни продлить
её. Вход по коду на почту убирает эту зависимость: сайту нужен только он сам и почта.

## Как это работает

- На странице входа человек вводит адрес, получает письмо с шестизначным кодом и вводит код.
- Новый адрес получает **учётную запись сайта**. У неё отрицательный внутренний номер, за ней
  нет Telegram, и бот ей никогда не пишет. Всё остальное то же: оферта, пробный период,
  подключение, оплата СБП на сайте.
- Пользователь Telegram может **привязать адрес** в профиле на сайте. После этого вход по почте
  открывает ту же учётную запись с той же подпиской. Это стоит сделать заранее, пока Telegram
  доступен (через VPN).
- Один адрес — одна учётная запись, и наоборот.

Защита: код действует 10 минут и один раз; пять неверных попыток его сжигают; не больше
одного письма в минуту и пяти в час на адрес и на отправителя; ответ сервера не говорит,
зарегистрирован ли адрес; код хранится только в виде хеша; адрес и код не пишутся в журнал.

## Что нужно, чтобы включить

Письма уходят с адреса `noreply@cyberdefency.com` с именем «Cyberdefency». Личный адрес владельца
клиенты не видят: он нужен только для входа в почтовый сервис. Пока `SMTP_HOST` пуст, вход по
почте выключен, а сайт отвечает `email_login_unavailable`.

Свой почтовый сервер на VPS для этого не годится: письма с адресов хостингов почти всегда
попадают в спам, а порт 25 у многих хостингов закрыт. Нужен сервис отправки писем, который
подтверждает домен записями DNS. Ниже Resend (бесплатно до 3000 писем в месяц); Brevo и другие
устроены так же, меняются только адрес сервера и логин.

1. Зарегистрироваться на resend.com.
2. **Domains → Add Domain** → `cyberdefency.com`. Сервис покажет несколько DNS-записей (MX и TXT
   для отправки, TXT для DKIM).
3. В Cloudflare, зона `cyberdefency.com` → **DNS** → добавить эти записи как есть, **DNS only**
   (серое облако). Существующие записи не трогать.
4. Дождаться в Resend статуса **Verified** (обычно минуты).
5. **API Keys → Create API Key**, доступ **Sending access**, только этот домен. Ключ показывается
   один раз: его не пересылать в чат, а сразу вставить на сервере (шаг 7).
6. **DE**, настройки:

   ```bash
   cd /root/vpn-src && bash scripts/update_bot.sh --set SMTP_HOST=smtp.resend.com SMTP_PORT=465 SMTP_SECURITY=tls SMTP_USERNAME=resend SMTP_FROM=noreply@cyberdefency.com
   ```

7. **DE**, ключ (вводится скрыто, в истории и выводе не остаётся):

   ```bash
   cd /root/vpn-src && bash scripts/update_bot.sh --set-secret SMTP_PASSWORD
   ```

8. Проверка: на сайте «Вход по почте» → свой адрес → письмо должно прийти от
   «Cyberdefency <noreply@cyberdefency.com>». Если оно попало в спам, отметить «Не спам».

| Настройка | Значение |
|---|---|
| `SMTP_HOST` | Сервер исходящей почты |
| `SMTP_PORT`, `SMTP_SECURITY` | `465` и `tls` или `587` и `starttls` |
| `SMTP_USERNAME` | Логин (у Resend это слово `resend`) |
| `SMTP_PASSWORD` | Пароль или ключ API. Секрет: только через `--set-secret` |
| `SMTP_FROM` | Адрес отправителя |
| `SMTP_FROM_NAME` | Имя рядом с адресом, по умолчанию `Cyberdefency` |

Если сервер не может соединиться с почтовым сервисом (в журнале бота `mail_send_failed`, на
сайте «Не удалось отправить письмо»), проверьте порт с DE:
`timeout 8 bash -c "</dev/tcp/smtp.resend.com/465" && echo open || echo closed`. У хостинга DE
порт 465 закрыт (14 ноября 2026); Resend принимает те же соединения на 2465 (TLS) и 2587
(STARTTLS): `update_bot.sh --set SMTP_PORT=2465 SMTP_SECURITY=tls`.

Почтовый сервис получает адрес клиента и текст письма с кодом: его нужно назвать в политике в
разделе о получателях данных.

## Порядок обновления

Вход по почте добавляет в базу две таблицы и новые операции шлюза базы. Шлюз на RU обновляется
первым, бот вторым (`RU_DATABASE_CUTOVER.md`, «После переноса», «Обновления»): бот с новыми операциями не
стартует против старого шлюза и скажет об этом.

## Что это меняет в документах

В политику (`legal/privacy.md`) добавлены строки про адрес электронной почты для входа: цель,
срок хранения. Адрес передаётся почтовому сервису для доставки письма; какой это сервис,
зависит от выбранного ящика, и это нужно вписать в раздел о получателях данных. Формулировки
стоит показать юристу вместе с остальным (`LEGAL_BRIEF.md`).

## Чего он не делает

- Не привязывает учётную запись сайта к Telegram задним числом: если человек сначала завёл
  запись по почте, а потом пришёл в бота, это две записи. Объединение записей не сделано.
- Не шлёт напоминаний о сроке подписки на почту. Учётной записи сайта доступны уведомления
  браузера (push), если их включить.
