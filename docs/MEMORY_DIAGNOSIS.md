## Воспроизведение в облачной копии, без запуска приложения

Python 3.11.17, aiogram 3.31.0, pydantic-settings 2.5.2. Процессы только
импортировали модули, без production-секретов, БД или подключения к Telegram.
Для сравнения использовались `/proc/self/status` и одинаковые прочие зависимости.

| Этап | Pydantic 2.9.2, RSS | Pydantic 2.13.5, RSS |

| Только импорт aiogram | 436272 КиБ ≈ 426 МиБ | 173452 КиБ ≈ 169 МиБ |
| Импорт main и зависимостей | 468860 КиБ ≈ 458 МиБ | 211576 КиБ ≈ 207 МиБ |

Разница полного импорта — около 251 МиБ (55%). Это не измерение полного

обработчиков, HTTP-клиенты, БД, нагрузка и особенности системных библиотек.
Высокий базовый расход старого набора воспроизводится; утечка при длительной
работе отдельно не установлена и не исключена.

## Подготовленное изменение

В `requirements.txt` закреплён `pydantic==2.13.5` вместо 2.9.2.
Метаданные установленного aiogram 3.31.0 допускают Pydantic >=2.4.1,<2.14;
pydantic-settings 2.5.2 требует >=2.7.0. Вместе с Pydantic меняются
pydantic-core и typing-inspection согласно его зависимостям.

Изменение проверено сначала в отдельном virtualenv. На production ничего
не устанавливалось и рабочие контейнеры не перезапускались. До предложения
переключения нужно подтвердить версии в действующем образе, затем собрать и
проверить отдельный кандидат. Не выполнять pip install в рабочем контейнере:
это не даёт воспроизводимого образа и может оставить частично изменённый runtime.
Не снимать лимит памяти и не увеличивать его вслепую вместо диагностики.
