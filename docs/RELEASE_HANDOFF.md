# Проверенная версия и порядок завершения запуска

Эта версия подготовлена в облачной рабочей копии `/workspace/VPN`.
Её локальная проверка не означает установки на VPS. Сохранённые ранее рабочие
образы, настройки и проверенные резервные копии нужны для отката.

## Что изменено

- ЮKassa: заказ и неизменяемый запрос сохраняются до обращения к провайдеру.
  Повторное нажатие оплаты того же тарифа/периода возвращает существующий счёт.
  После таймаута используется тот же ключ идемпотентности, максимум 23 часа.
  Неразрешённый результат после этого срока требует проверки оператором;
  новый счёт автоматически не создаётся. Смена магазина также блокирует повтор.
- Бот раз в минуту проверяет ожидающие платежи через API ЮKassa и Crypto Pay,
  включая случаи пропущенного webhook. За проход обрабатываются до 25 платежей
  и 5 незавершённых созданий счетов, до 3 запросов одновременно, с бюджетом
  45 секунд и сохранённым расписанием повторов. Большая очередь увеличивает
  время проверки. Ошибка API не является отменой оплаты.
- Повторные/одновременные подтверждения не добавляют оплаченный период дважды.
  Исторические платежи, ранее уже помеченные `cancelled`, автоматически не
  пересматриваются: их нужно сверить с провайдером отдельно.
- Напоминание за 3 дня сохраняет отметку доставки только после успешного ответа
  Telegram. При ошибке отправка повторяется в следующем проходе.
- PWA и Mini App собираются на Node 22; Caddy обновлён до 2.11.7, модуль
  ограничения запросов закреплён на v0.1.0. Исправлены заголовки встраивания
  Mini App, адрес `/tma`, передача IP через локальный прокси и запуск без caps.
- Для действующего DE подготовлен отдельный веб-контейнер на loopback 18082,
  без конфликта с Marzban Caddy на 80/8443.
- Добавлены архиватор подтверждённых AUTOBAN старше 30 дней с AES256 и проверкой
  расшифрования до удаления, а также отдельная выгрузка зашифрованных архивов
  в R2 с полной обратной загрузкой и сравнением SHA256.

USDT остаётся вне обычного меню, доступен по запросу через Telegram. Рабочие
аккаунты, оплаты и акцепт оферты остаются в БД; обычная телеметрия выключена
по умолчанию. Автобан по эвристике не является безошибочным доказательством
преступления; безопасный режим `AUTOBAN_MODE=review` сохранён.

## Порядок установки на имеющиеся серверы

1. **Доступ.** Для работы агента нужны фактический разрешённый SSH-маршрут
   к 89.125.210.172:22 и 45.138.157.65:22 и SSH-учётные данные в поддерживаемой
   среде. Одно разрешение в чате эти соединения не создаёт. Последняя проверка
   файла политики среды показала пустой список TCP-доступа и отсутствие SSH-agent.
   Cloudflare API-токен ранее получил 401; значения токенов в чат не отправлять,
   рабочее значение задаётся в секрете среды `CLOUDFLARE_API_TOKEN`.
2. **Инвентаризация.** На каждом сервере из каталога новой версии запустить:

   ```bash
   python3 scripts/diagnose_payment_path.py --role de
   ```

   На российском сервере вместо `de` указать `ru`. Скрипт выводит состояние
   служб, HTTP-коды и булевы признаки настроек, без токенов/командных строк служб.
   Пустой webhook не создаёт платёж. Его 200 означает достижимость обработчика,
   но не успешную оплату. Корень RU nginx штатно может возвращать 404.
3. **Резервная копия.** На DE выполнить уже проверенный владельцем
   `/root/backup-live-vpn.sh`, проверить восстановление обеих БД и сохранить
   шифрованный архив отдельно от ключей. Не копировать активный SQLite обычным
   `cp`, не удалять прежние образы и контейнер Amnezia.
4. **Кандидат бота.** Сборка `docker build --target bot -t node-rental-bot:release .`
   выполняется из новой версии. До переключения проверить её на online-копии
   рабочей SQLCipher-БД с прежним DB_KEY и без Telegram polling; миграции только
   добавляют таблицы/индексы. Сохранить точный прежний ID образа. Переключать
   только сервис bot существующего Compose; полный `compose up` из корня новой
   версии на этом сервере конфликтует с уже работающим Caddy. Не переносить
   `.env.example` поверх рабочей `.env` и не генерировать новый DB_KEY.
5. **Приложение/оферта.** Применить [WEB_DEPLOYMENT.md](WEB_DEPLOYMENT.md), включая
   локальную проверку, добавление сайта в существующий Caddy и обратимый reload.
   Настроить BotFather: Login domain `app.cyberdefency.com`, Mini App
   `https://app.cyberdefency.com/tma/`. Проверить Android и браузер отдельно.
6. **Оплата.** Настройки провайдера: `SBP_PROVIDER=yookassa`,
   `YOOKASSA_EGRESS=ru_gateway`, `YOOKASSA_PROXY_URL=http://10.203.0.1:3128`.
   Значение `SBP_PROVIDER=test` не поддерживается: тестовый режим определяется
   магазином и ключом. Ключ хранится в Docker secret, не в Git/команде/чате.
   Проверить соответствие shopId/ключа на `/v3/me` через RU-шлюз. Для боевого
   магазина выполнить `scripts/prepare_yookassa.py` и
   [YOOKASSA_MY_TAX_SETUP.md](YOOKASSA_MY_TAX_SETUP.md).
7. **Tunnel.** На RU connector должен быть Healthy, публичный hostname
   `pay.cyberdefency.com` должен вести на `http://127.0.0.1:18080`.
   Цепочка: Cloudflare → RU 18080 → WireGuard DE 18081 → бот 8080.
   В ЮKassa уведомление `payment.succeeded` направляется на
   `https://pay.cyberdefency.com/yookassa/webhook`. Последняя внешняя проверка
   ранее получила 521. Новая проверка получает 403 / Cloudflare 1010:
   [исправление Browser Integrity Check](PAYMENT_WEBHOOK_CLOUDFLARE.md).
   Исправление серверной цепочки здесь не подтверждено.
8. **Приёмка оплаты.** Создать счёт из бота, оплатить тестовым способом ЮKassa,
   сверить `succeeded/paid` у провайдера, одну запись paid в БД и выдачу доступа
   Marzban. Повтор уведомления не должен добавлять срок. Затем проверить VPN
   с ПК/Android и доступность после перезагрузки. Локальные тесты заменяют
   провайдеров тестовыми HTTP-ответами, поэтому не заменяют эту приёмку.
9. **Архивы.** Установить архиватор по [COMPLIANCE_ARCHIVE.md](COMPLIANCE_ARCHIVE.md)
   только после подготовки отдельного холодного диска/ключей. Ежедневный запуск
   в 03:24 Asia/Novosibirsk означает окно 30–31 сутки. SQLite не поддерживает
   неблокирующий аналог PostgreSQL pg_repack; автоматического VACUUM нет.
   Для R2 использовать [R2_BACKUP.md](R2_BACKUP.md). Реальная загрузка в R2
   требует имени бакета и действующего S3-профиля на сервере; пока не проверена.
10. **Запуск продаж.** Подключить боевой магазин/чеки, проверить оферту с учётом
    фактической фильтрации. Xray-политика автоматически не применяется к
    AmneziaWG. Рекламные материалы остаются черновиками: расходы не разрешены
    прежним заданием и здесь не запускались. Нет обещания полной анонимности,
    абсолютной устойчивости к блокировкам или отсутствия любых будущих ошибок.

## Проверки этой поставки

`make check`: Ruff, форматирование, mypy, скан секретов, Bandit и аудит Python
зависимостей прошли; 234 теста прошли. Bandit оставляет прежнее предупреждение
о ненужной аннотации B603, уязвимостей в этом запуске не сообщил.
Собранный bot-image отдельно проверен без сети, с SQLCipher: health 200,
закрытый API 401, пустое уведомление ЮKassa 200. Это не реальная транзакция.
Все 234 теста также отдельно прошли с SQLCipher вместо обычного SQLite.
Новый веб-образ Caddy 2.11.7 проверен реальными HTTP-запросами к PWA, Mini App,
оферте и прокси: внутренние маршруты закрыты, клиентский IP передаётся корректно,
запуск работает от uid1000 с read-only filesystem и сброшенными capabilities.

Производственные JS-зависимости имеют нулевой результат npm audit; полный
аудит инструментов сборки содержит 10 low/moderate предупреждений в цепочке
Workbox, без high/critical. Принудительное несовместимое понижение/замена этих
пакетов не выполнялось. Веб-образ сборочной проверки содержит техническое имя
бота: для сервера он пересобирается с настоящим `VITE_BOT_USERNAME`.
