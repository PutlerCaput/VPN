# Сравнение с AmneziaVPN — 6 ноября 2026

Источники: README клиента <https://github.com/amnezia-vpn/amnezia-client>,
описание протокола <https://github.com/amnezia-vpn/amneziawg-go>. Владелец сам
пользуется AmneziaVPN на Android с собственным сервером в Германии.

AmneziaVPN — это в первую очередь **приложение**: оно ставит VPN-контейнеры
на сервер пользователя по SSH и подключается к ним разными протоколами. Наш
проект — **сервис подписки**: бот, оплата, выдача доступа, учёт трафика.
Поэтому переносятся не все возможности: «свой сервер в один клик» для
клиентов сервиса не нужен — сервер уже есть у владельца.

## 1. Возможности

| AmneziaVPN | У нас было | Стало | Комментарий |
|---|---|---|---|
| Протокол **AmneziaWG** (WireGuard с маскировкой: мусорные пакеты, дополнение рукопожатия, свои заголовки) | нет (только VLESS + Reality) | **Есть**: отдельный сервер AmneziaWG, ключи выдаёт бот | Отдельный контейнер `cyberdefency-awg`; рабочий `amnezia-awg2` владельца не меняется |
| XRay (VLESS + Reality) | есть | без изменений | Оба протокола доступны одной подписке |
| OpenVPN over Cloak, Shadowsocks, IKEv2, WireGuard | нет | не добавлены | AmneziaWG и Reality закрывают задачу маскировки; ещё один протокол — ещё один сервер для поддержки |
| Ключ на каждое устройство, отзыв отдельного ключа | одна ссылка на всех (сброс отключает всех) | **Есть** для AmneziaWG: `/amnezia` → добавить / получить / удалить; число ключей = лимиту устройств тарифа | Это ещё и первое техническое ограничение числа устройств |
| Импорт по файлу и QR-коду | QR для VLESS | **Есть**: файл `.conf` и QR для каждого устройства | Подходит для AmneziaVPN, приложений AmneziaWG и роутеров с AmneziaWG |
| Одно приложение для всех систем | разные клиенты по системам | **AmneziaVPN рекомендуется** в инструкции `/connect` для AmneziaWG | Ссылка на официальный раздел Releases |
| Раздельное туннелирование (сайты; приложения — Android и ПК) | нет | Работает в приложении AmneziaVPN с нашим файлом | Настраивается пользователем в приложении |
| Kill switch | инструкция | без изменений + блокировка IPv6 мимо туннеля (`AllowedIPs ::/0`) | |
| Защита от утечек DNS | — | В файле указан DNS, запросы идут через туннель | |
| Роутеры (Keenetic с AmneziaWG) | нет | Файл `.conf` подходит | Настройка на стороне пользователя |
| Свой сервер в один клик | — | неприменимо | У сервиса один владелец серверов |
| Открытый исходный код | закрытый проект | неприменимо | Решение владельца |
| Amnezia Premium: много стран | одна страна | Подписка со всеми серверами (прошлый этап) | Нужны дополнительные серверы |

## 2. Как это устроено

```text
Бот (node-rental-bot-1) ── HTTP + токен ──► cyberdefency-awg:8090 (агент)
         │                                     │ awg set / show
         │  сверка каждые 3 мин                ▼
         │                               amneziawg-go, UDP 39051, 10.67.0.0/24
         ▼
      Marzban (VLESS)                    клиенты: AmneziaVPN / AmneziaWG
```

- `deploy/awg/` — образ сервера: `amneziawg-go v3.1.20260828` (без модуля
  ядра) и `amneziawg-tools v3.1.20260812`, собираются из официальных исходников;
  агент на стандартной библиотеке Python.
- Параметры маскировки AmneziaWG 1.0 (Jc, Jmin, Jmax, S1, S2, H1–H4)
  генерируются один раз при первом запуске и понятны старым и новым клиентам.
- Изоляция: клиенты туннеля не видят агент, сам сервер, частные сети Docker и
  хоста и друг друга — только интернет.
- Бот — источник правды. Каждые 3 минуты он включает ключи активных подписок,
  отключает ключи истёкших, заблокированных и исчерпавших трафик, удаляет
  забытые ключи.
- **Общий лимит трафика.** Счётчиком остаётся Marzban: бот уменьшает лимит
  пользователя в Marzban на трафик AmneziaWG текущего 30-дневного окна, и
  в `/status` показывается сумма. Пока лимит не исчерпан, работают оба
  протокола; после исчерпания — ни один, до обнуления.
- Ключи устройств хранятся в базе бота (в production она зашифрована
  SQLCipher), чтобы файл можно было получить повторно.

## 3. Проверено

`deploy/awg/e2e_test.sh` — настоящий сервер и клиент AmneziaWG в Docker:
сайт открывается через туннель и видит адрес сервера; агент, сам сервер и
частные сети через туннель недоступны; трафик считается; отключённый ключ
перестаёт работать, включённый снова — работает; после перезапуска сервера
ключи восстанавливаются; удаление работает. Сверка бота, ключи, лимиты и
интерфейс покрыты тестами `tests/test_awg.py`.

## 4. Установка (DE-сервер, после обновления бота)

Команды — в PowerShell на ПК.

```powershell
ssh root@89.125.210.172 'bash /root/vpn-update/*/scripts/install_awg.sh /root/vpn-update/*'
```

Только проверка: найдёт сеть бота, публичный адрес, проверит, что UDP 39051
свободен, и покажет существующие контейнеры Amnezia — их не трогает. Затем:

```powershell
ssh root@89.125.210.172 'bash /root/vpn-update/*/scripts/install_awg.sh /root/vpn-update/* --apply'
```

Ожидаемо: `AWG_RUNNING`, `BOT_CAN_REACH_AGENT`, `AWG_INSTALL_OK`. Если у
хостинга есть свой межсетевой экран в панели, откройте там UDP 39051.

Отключить: `bash /root/vpn-update/*/scripts/install_awg.sh --remove` и
`bash /root/vpn-update/*/scripts/update_bot.sh --set AWG_ENABLED=false`.
Ключи сервера сохраняются в томе Docker, поэтому повторный запуск выдаёт те
же параметры и клиентам ничего не нужно менять.

## 5. Ограничения

- Если UDP до немецкого сервера у части операторов режется, AmneziaWG у них
  работать не будет; VLESS через RU-relay остаётся. Можно направить AmneziaWG
  через RU-сервер (переменная `AWG_ENDPOINT_HOST` и UDP-проброс на RU) — это
  отдельная настройка сервера, автоматически не выполняется.
- Маскировка затрудняет распознавание, но не гарантирует работу в любой сети.
- Скорость userspace-реализации ниже модуля ядра; для пилота это не заметно.
