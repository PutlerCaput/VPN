# Платёжные изменения — подготовленная версия, 2 ноября 2026

## Запрос владельца

В публичной оферте описываются расчёты в рублях через ЮKassa. Упоминания
USDT и Crypto Pay, отдельная валютная таблица и раздел 3.Б удалены. Убран
ручной перевод/QR исполнителя как альтернатива ЮKassa. Буквального упоминания
«Моби.Деньги» в предоставленной локальной оферте не было; присутствовало
название оператора ЮKassa «ЮМани», скобки с ним убраны из платёжного пункта.
Это не утверждение о том, что «Моби.Деньги» и «ЮМани» — одна организация.

Расчёты по этой оферте описаны отдельно от доступного в Telegram сценария
USDT. Перед отдельной оплатой пользователю показываются её условия, сумма,
тариф и срок. В команде `/usdt` удалена ссылка на отсутствующий раздел
оферты. Наличие отдельного сценария не скрывается от плательщика перед
подтверждением счёта. Условия ранее оплаченных подписок этим изменением
не переписываются.

## Изменённые компоненты

- `legal/oferta.md`: новая подготовленная редакция от 02.11.2026, рублёвые
  тарифы сохранены; публичные платёжные пункты — ЮKassa.
- `handlers/payments.py`, `keyboards/main_menu.py`: обычный экран ЮKassa,
  отдельная `/usdt` с самостоятельным описанием. В USDT-сценарии исправлена
  валюта вводного описания тарифов.
- `services/billing.py`: при отсутствии настроенного клиента ЮKassa новый
  обычный рублёвый счёт не превращается в ручной перевод. Возвращается
  `ruble_payments_unavailable`. Legacy-СБП остаётся только явной внутренней
  опцией совместимости; обычный `main.build_services` её не включает.
- PWA: обычная оплата только через ЮKassa, нет выбора криптовалюты/ручного QR.
- Mini App: обычные цены в рублях, покупка в боте через ЮKassa.
- Обновлены связанные публичные платёжные тексты/маркетинговый черновик.

Crypto Pay, подписи webhooks, обработка ранее выставленных счетов, история
USDT и внутренний платёжный API сохранены. Изменение публичных экранов не
является изоляцией API по типу устройства или проверкой географии клиента.

## Проверки

134 теста прошли на SQLite, 134 — на SQLCipher. Существующие проверки ЮKassa,
Crypto Pay и обработки платежей сохранены. Добавлены проверки отказа от
неявного ручного fallback и создания USDT-счёта при отключённом legacy-СБП.
Для старых регрессионных тестов с симуляцией ручного СБП совместимость
включена явно; обычный production-конструктор использует безопасный default.
Ruff/format/mypy/Bandit/secret scan пройдены; PWA и Mini App собираются.
Реальные платежи не создавались, внешние платёжные системы не вызывались.

## Production остаётся отдельным этапом

На сервере пока установлено только исправление памяти. Перед применением
платёжных изменений нужно проверить действующий SBP_PROVIDER, наличие
настроенной ЮKassa/Crypto Pay и отпечатки изменяемых файлов, не печатая ключи.
Нельзя заменить действующую оферту целиком облачным черновиком: в нём уже
есть новая политика журналирования, ещё не внедрённая на сервере.
Платёжный раздел серверной оферты обновляется отдельно с сохранением других
действующих положений и резервной копии прежнего текста.

Telegram и обе веб-версии получают текст из `legal/oferta.md` через
`handlers.legal.offer_text`. Функция кешируется: изменение файла на диске
само по себе не обновляет текст уже запущенного процесса. На сервере файл
встроен в образ, поэтому потребуется проверенный образ-кандидат и перезапуск
только бота; установка новой версии целиком может запускать миграции БД и
не должна подменять это точечное изменение. Порядок публикации новой редакции
и ранее акцептованные условия сохраняются и учитываются при развёртывании.
