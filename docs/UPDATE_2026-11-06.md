## 2. Как устроены новые тарифы

- Тариф «Стандарт» включается строкой `ENABLED_TIERS=standard` в `.env`. Без неё
  бот продаёт прежние Basic/Complete/Prime: обновление кода само не меняет
  условия для текущих клиентов.
- Квоту применяет панель Hiddify Manager (`data_limit`, сброс `month` = каждые 30 дней
  от создания или прошлого сброса). Это переживает перезапуск бота и повторные
  уведомления об оплате. Оплата нового периода счётчик не обнуляет.
- Пробный период: 24 ч и `TRIAL_TRAFFIC_GB` (в примере 3 ГБ, по умолчанию без
  лимита). Тариф пробного периода — первый в `ENABLED_TIERS`.
- Лимит 2 устройств — **условие оферты, а не техническая блокировка**: Hiddify Manager
  не умеет считать устройства, а число IP-адресов не равно числу устройств.
  Инструмент поддержания лимита — сброс ссылки.
- Превышение квоты останавливает подключение до обнуления счётчика. Это не бан.
- Оферта (`legal/oferta.md`, редакция 06.11.2026): тариф «Стандарт», п. 3.6
  «Трафик», Telegram Stars, возврат звёзд, `/paysupport`. Текст нужно проверить
  юристу. По п. 8.2 новая редакция публикуется за 7 дней до вступления в силу.

Репетиция: «старый» бот собран из исходного снимка архива, запущен с
зашифрованной базой и данными, затем обновлён `scripts/update_bot.sh`:

1. проверка без изменений → `MIGRATION_CHECK_OK`, `CHECK_OK`;
2. `--apply --env-add` → `UPDATE_OK`, бот healthy, база мигрирована, данные на месте;
3. намеренно сломанная сборка → бот не стал healthy → автоматический откат на
   прежний образ и прежний `.env`, бот снова healthy;
4. ручной откат к самой первой версии → healthy; старая версия работает с уже
   мигрированной базой.

Не проверено: настоящая оплата Stars, Telegram API, панель Hiddify Manager на сервере,
доставка уведомлений, сеть RU↔DE, Cloudflare. Локальные тесты используют
заглушки.

## 4. Установка на сервер DE (выполняет владелец)

Что делает `scripts/update_bot.sh`: сохраняет текущий образ бота для отката,
собирает новый, делает проверенную копию базы, прогоняет миграцию **на копии**,
и только с `--apply` переключает контейнер бота. Если новый бот за 2,5 минуты
не стал healthy — сам возвращает прежний образ и `.env`. Hiddify Manager, AmneziaWG,
Caddy, секреты и ключ базы не затрагиваются.

**Шаг 1. На ПК, PowerShell.** Скачайте ZIP этой ветки на GitHub
(Code → Download ZIP) в «Загрузки», затем:

```powershell
scp "$env:USERPROFILE\Downloads\VPN-ccr-67b53ac3-v9lutm.zip" root@89.125.210.172:/root/vpn-update.zip
ssh root@89.125.210.172 'rm -rf /root/vpn-update && python3 -m zipfile -e /root/vpn-update.zip /root/vpn-update && cd /root/vpn-update/* && bash scripts/update_bot.sh $PWD'
```

Ожидаемый конец вывода: `MIGRATION_CHECK_OK` и `CHECK_OK`. Живой бот при этом
не меняется. Если вместо этого `UPDATE_FAILED: ...` — ничего не изменено,
пришлите вывод.

**Шаг 2. Переключение** (после `CHECK_OK`):

```powershell
ssh root@89.125.210.172 'cd /root/vpn-update/* && bash scripts/update_bot.sh $PWD --apply --env-add'
```

`--env-add` добавляет в `.env` только отсутствующие строки `STARS_ENABLED=true`,
`STARS_RUB_PER_STAR=1.60`, `YOOKASSA_IN_BOT=false`, `TRIAL_TRAFFIC_GB=3` и не
меняет существующие. Ожидаемо: `UPDATE_OK` и строка с командой отката.

**Шаг 3. Новый тариф** — когда оферта опубликована и проверена:

```powershell
ssh root@89.125.210.172 'bash /root/vpn-update/*/scripts/update_bot.sh --set-tiers standard'
```

Скрипт сохраняет копию `.env`, ставит `ENABLED_TIERS=standard`, перезапускает
только бота и ждёт healthy; если бот не принял настройку — возвращает прежний
`.env`. Ожидаемо: `TIERS_OK ENABLED_TIERS=standard`.

**Откат**: полную команду печатает шаг 2 (`bash /root/vpn-update/.../scripts/update_bot.sh --rollback node-rental-bot:rollback-<время> <копия .env>`). Если тариф уже переключён, указывайте копию `.env`, сделанную до обновления: прежняя версия бота не знает тариф `standard`.

Сайт (PWA, Mini App, онлайн-оферта) собирается отдельным контейнером и
разворачивается по [WEB_DEPLOYMENT.md](WEB_DEPLOYMENT.md); скрипт его не трогает.
