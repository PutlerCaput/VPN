# Hiddify Manager

The bot provisions access through [Hiddify Manager](https://github.com/hiddify/Hiddify-Manager)
API v2. It does not talk to any other panel.

Official references:

- [How to use the API](https://hiddify.com/manager/contribution/How-to-use-API-in-HiddifyManager-project/)
- Admin user handlers and schemas in [hiddifypanel](https://github.com/hiddify/hiddifypanel)
  (`UsersApi`, `UserApi`, `PostUserSchema`, `PatchUserSchema`)

## Authentication

Every admin request uses the header `Hiddify-API-Key: <admin UUID>`.
The UUID is taken from the panel (an admin account), stored as the Docker
secret `secrets/hiddify_api_key.txt`, and read as `HIDDIFY_API_KEY`.

The admin proxy path (Settings → Advanced Settings → Admin Proxy Path) is
`HIDDIFY_ADMIN_PROXY_PATH`. The user proxy path, used only to build public
subscription URLs, is `HIDDIFY_USER_PROXY_PATH`.

## Endpoints the bot uses

Base: `{HIDDIFY_URL}/{HIDDIFY_ADMIN_PROXY_PATH}/api/v2/`

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/admin/user/` | Create a user (UUID is generated by the bot) |
| GET | `/admin/user/{uuid}/` | Read a user |
| PATCH | `/admin/user/{uuid}/` | Update expiry, quota, enable/disable, or rotate the UUID |
| GET | `/admin/user/` | List users (usage / abuse checks) |
| GET | `/panel/ping/` | Liveness |
| GET | `/panel/info/` | Panel version |

`PATCH` may include a new `uuid`. That is how `revoke_subscription` invalidates
every previously issued link: the old UUID stops working, and the database
`node_username` is updated to the new one.

## UUID handling

- `create_user` generates a UUID4, stores it in `users.node_username` *before*
  calling the panel (so a retry reuses the same UUID), and sends it as `uuid`
  in `POST /admin/user/`.
- `revoke_subscription` PATCHes a new UUID4, then writes it back to
  `node_username` and issues a new subscription URL.

The public subscription URL is:

`{SUBSCRIPTION_BASE_URL or HIDDIFY_URL}/{HIDDIFY_USER_PROXY_PATH}/{uuid}/`

Clients such as Hiddify, v2rayNG and Streisand import that URL.

## Environment

See `.env.example`. Required:

- `HIDDIFY_URL` — HTTPS origin of the panel
- `HIDDIFY_API_KEY` — admin UUID (secret file)
- `HIDDIFY_ADMIN_PROXY_PATH` — admin proxy path
- `HIDDIFY_USER_PROXY_PATH` — user proxy path (for subscription links)
- `SUBSCRIPTION_BASE_URL` — public HTTPS origin if it differs from `HIDDIFY_URL`

Traffic: the bot's `data_limit` in bytes is sent as `usage_limit_GB`. An
unlimited quota (0 bytes in the bot) is sent as `10000` GB, a sentinel the
client maps back to unlimited. Reset strategies map to Hiddify `mode`
(`day` → `daily`, `week` → `weekly`, `month` → `monthly`, `no_reset` → `no_reset`).

Nothing in this document is applied to a live server automatically. Deploy the
panel and the bot together, then point these settings at the new panel.
