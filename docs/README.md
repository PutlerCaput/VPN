## Правила работы с документацией и резервными копиями

1. Сначала сверяйте дату и статус документа. Файл с названием «план» не подтверждает, что действие выполнено.
2. `DEPLOYMENT_STATE.md` — журнал исторических снимков, а не live-инвентаризация.
3. Изменения production выполняются только после backup, проверки команды и понятного отката.
4. Репозиторий публичный: не коммитить `.env`, `secrets/`, базы, Docker inspect, SSH/age private keys, клиентские ссылки и резервные архивы.
5. Зашифрованные архивы хранить вне Git-истории. Для GitHub допустим только отдельный приватный backup-репозиторий/защищённое хранилище после проверки политики доступа; не загружать резервные копии в этот публичный репозиторий.
6. После восстановления проверить контрольные суммы, целостность SQLCipher/Hiddify и тестовый запуск на изолированном сервере.
