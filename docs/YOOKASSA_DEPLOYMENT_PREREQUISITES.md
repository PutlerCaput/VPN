# ЮKassa: фактические prerequisites перед переключением

Пошаговое подключение автоматических чеков самозанятого: [YOOKASSA_MY_TAX_SETUP.md](YOOKASSA_MY_TAX_SETUP.md).

По выводу владельца после memoryfix на production:

- SBP_PROVIDER=manual;
- совокупная готовность YOОKASSA_CONFIGURED=false (какое из двух полей отсутствует,
  ещё не уточнено); не считать оба поля отсутствующими без отдельной проверки;
- Crypto Pay настроен, CRYPTO_PAY_TESTNET=false; это не доказательство
  работоспособности доставки webhook и реального зачисления платежа.
- Действующая оферта содержит «Моби.Деньги», а «ЮМани» не содержит.
  Поэтому локальный архив не является точной копией серверного текста.

публичные настройки (без ключей), затем подготовить точечный патч.

## Последовательность

Уточнение владельца от 3 ноября 2026: основная кнопка «Оплата» не отвечает;
есть также секретный ключ тестового магазина. Отсутствие настроенной ЮKassa
само по себе не объясняет молчание начального меню в имеющейся копии кода:
`menu_pay` вызывает `show_channels` без обращения к провайдеру. До изменения
конфигурации необходимо проверить актуальный серверный обработчик и свежую
ошибку. `scripts/diagnose_payment_button.py` читает выбранные публичные части
исходников и выводит только типы ошибок, места в коде и фиксированные признаки
из последних 300 строк журнала за 5 минут; не перезапускает сервис, не открывает
БД и не обращается к Telegram или платёжным API.

`scripts/prepare_yookassa.py` предназначен для отдельной проверки **рабочего**
магазина GET /me и подготовки закрытого каталога с проверенными credentials.
Он отвергает `test=true` и не применяет настройки production. Тестовый ключ
нужно использовать отдельно, с изолированной тестовой БД и заглушкой выдачи
доступа; тестовые платежи не должны продлевать реальные подписки.

Получен действующий раздел оферты 3.1–3.5.4. Подготовленная редакция 3.5
теперь сохраняет его нумерацию, убирает МОБИ.Деньги и ручные переводы,
сохраняет НПД, условно описывает интеграцию с «Моим налогом» и не содержит
USDT. На сервере заменять только этот подраздел, не всю облачную оферту.

1. Уточнить готовность магазина ЮKassa и наличие выданных shopId/ключа.
   Проверить раздельную готовность текущих привязок; переиспользовать имеющиеся.
   Значения не передавать в чат, не добавлять в историю команд или исходники.
2. Прочитать текущий публичный платёжный раздел и определить отличие интерфейса.
   Пока это подготовка; публичная оферта не должна выдаваться за подтверждение
   работающего подключения платёжного провайдера.
3. При готовом магазине проверка учётных данных — только GET
   `https://api.yookassa.ru/v3/me`, без создания платежей. Секрет вводится
   скрыто в терминале владельца или читается из уже существующего binding.
   Проверить совпадение магазина, `test=false`, `status=enabled`; не печатать
   API-ответ целиком, Authorization, shopId или ключ. Не следовать редиректам
   с Basic Auth; сохранять TLS verification.
4. Проверить публичный HTTPS endpoint `/yookassa/webhook`, маршрутизацию Caddy,
   домен, сертификат и настройки уведомления `payment.succeeded`. Наличие ключа
   само по себе не обеспечивает автоматическое продление после оплаты.
5. Подготовить ограниченный image-кандидат для текущего приложения: платёжный
   раздел оферты, меню и при необходимости обработчик отдельного USDT-входа.
   Не внедрять одновременно новые схемы БД/политику журналирования.
6. После проверки клиента ЮKassa и webhook выполнить проверку счёта/обработки
   по согласованному сценарию. Не выполнять реальную оплату/возврат автоматически.
7. Переключить только бот с проверкой здоровья и сохранённым откатом.
   Обновить серверные исходники и сохранить предшествующую редакцию оферты.

До регистрации/активации магазина и предоставления пригодных credentials
запуск ЮKassa остаётся внешним blocker. Настроенный USDT не выключать и
не заменять тестовым токеном. Не имитировать успешную проверку магазина.

По решению владельца платёжный API должен выходить через RU-сервер, а бот и
VPN остаются в DE. Подготовленный маршрут использует Cloudflare Tunnel только
для публичного callback и отдельный HTTP CONNECT proxy внутри WireGuard для
исходящих API-запросов. Merchant secret остаётся на DE; RU не должен иметь
Docker Secret, DB, или прямой публичный CONNECT. Конфигурации ещё не установлены.
Cloudflare setup для зоны `cyberdefency.com`: [CLOUDFLARE_SETUP.md](CLOUDFLARE_SETUP.md).

Владелец сообщил о наличии тестового ключа. Ключ нужно применять только в
официальной тестовой среде с изолированной БД и без выдачи production-доступа.
Подключённый локальный payment client сейчас настроен на GET `/v3/me` для
боевого магазина и намеренно отвергает `test=true`; эта проверка не является
проверкой тестового ключа.

Для симптома «кнопка оплаты молчит» найдено: прежний production `channel_kb`
содержал пустую `InlineKeyboardButton()` без обязательного текста. Это вызывало
ошибку валидации меню до обращения к ЮKassa. Первая попытка исправления
завершилась с `COMMAND_FAILED:docker` до переключения. Владелец затем запустил
исправленный сценарий: получены `PAYMENT_MENU_STAGING_OK` и
`PAYMENT_MENU_FIX_DEPLOYED`; каталог отката —
`/root/vpn-payment-menu-20261103T060540Z-3z2djzsa`. По выводу владельца, платёжные
учётные данные и остальные сервисы не менялись. Сценарий устраняет ошибку
построения меню, но не подключает ЮKassa и не подтверждает оплату end-to-end.
Актуальность API-ключей и `YOOKASSA_CONFIGURED` нужно проверить отдельно перед
первым платёжным тестом.

## Проверенный официальный источник

В официальном SDK `yoomoney/yookassa-sdk-python`, класс Settings использует
`base_path = '/me'`, метод `get_account_settings` выполняет HTTP GET.

- https://github.com/yoomoney/yookassa-sdk-python/blob/master/src/yookassa/settings.py
- https://github.com/yoomoney/yookassa-sdk-python/blob/master/docs/examples/01-configuration.md

Документация примера возвращает account_id, test, fiscalization_enabled,
payment_methods и status. Набор доступных способов определяется конкретным
магазином. Не путать наличие банка/СБП на странице ЮKassa с новым платёжным
провайдером и не считать рабочий кабинет гарантией подключённого магазина.
