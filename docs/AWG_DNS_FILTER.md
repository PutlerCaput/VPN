# Фильтр DNS для AmneziaWG

Фильтр закрывает домены вредоносных и фишинговых сайтов, сайтов 18+ и азартных игр для
подключений AmneziaWG. Работает через собственный резолвер сервера (unbound), который
слушает только адрес туннеля `10.67.0.1`.

## Что делает

- Клиентский конфиг AmneziaWG содержит `DNS = 10.67.0.1`: приложение спрашивает имена у
  нашего резолвера, а не у публичных.
- Резолвер отвечает `NXDOMAIN` на домены из списков (с поддоменами) и пересылает остальные
  запросы публичным резолверам по DNS-over-TLS (Cloudflare, `@853`), чтобы провайдер не видел
  имён в открытом виде.
- Для клиентов туннеля закрыт DNS в обход резолвера: обычный и DNS-over-TLS (порты 53 и 853)
  на сторонние адреса отбрасываются в `FORWARD`. Поэтому нельзя просто указать в приложении
  публичный DNS и обойти фильтр.
- Списки: `nsfw`, `gambling` из репозитория hagezi/dns-blocklists и phishing.army (около 880
  тысяч доменов, около 403 МБ памяти в unbound). Адреса фиксированы в `scripts/awg_dns_update.sh`.
  Список угроз `tif` (1,46 млн доменов, около 950 МБ вместе с остальными) на сервере с 2 ГБ
  не помещается рядом с ботом и не используется.

## Чего фильтр **не** делает

- **DNS-over-HTTPS внутри браузера** (Chrome «Безопасный DNS», Firefox DoH) отправляет имена
  по HTTPS на сторонний адрес и мимо нашего резолвера. Фильтр этого не видит. Поэтому
  формулировка в тарифе: «по доменам при обычном DNS; браузерный DoH фильтр не проверяет».
  Пользователю стоит выключить «Безопасный DNS» в браузере.
- Блокировка по IP-адресам и содержимому страниц. Домен, открытый по адресу, не попадает
  в фильтр.
- Списки неполные по определению: новые вредоносные домены появляются раньше, чем попадают в
  списки.
- Фильтр не действует на старые конфиги. Конфиг с `DNS = 1.1.1.1` сохраняет адреса до тех пор,
  пока устройство не получит новый конфиг (см. «Переход»).

## Память, слишком большая зона и сторож

Контейнер AWG ограничен `mem_limit: 768m` в `deploy/awg/compose.yaml`. Если зона блокировки
снова окажется слишком большой, перезапустится только этот контейнер, а не весь сервер вместе
с ботом и Xray.

Агент не загружает зону, в которой больше 1 000 000 строк `local-zone` (тот же потолок, что
`MAX_DOMAINS`; 880 тысяч доменов занимали около 403 МБ, 1,2 млн — около 545 МБ). Такой файл
переименовывается в `blocklist.conf.too-large`, в лог пишется предупреждение, и фильтр
стартует пустым: DNS работает, блокировок нет. Зону нужно собрать заново:
`bash scripts/awg_dns_update.sh`.

Если unbound завершился, клиентам туннеля больше некуда спросить имя: файрвол закрывает любой
другой DNS. Сторож агента проверяет резолвер каждые 15 секунд и поднимает его снова.

`GET /healthz` (без токена) возвращает прежние поля и `"dns": true`, когда фильтр включён и
резолвер работает. Иначе `"dns": false`.

## Переход

1. Перед сборкой проверьте память: `free -m` на DE (доступно не меньше 500 МБ). Скрипт сам
   откажется собирать зону при нехватке памяти и оставит прежнюю; порог меняется переменной
   `MIN_AVAILABLE_MB`.
2. Пересоберите образ AWG (как при любом обновлении AWG) и перезапустите контейнер:
   `scripts/install_awg.sh` или `docker compose -f deploy/awg/compose.yaml up -d --build`.
   Клиенты на время перезапуска отключатся.
3. Соберите зону блокировки:
   ```
   bash scripts/awg_dns_update.sh
   ```
   Ожидается `AWG_DNS_UPDATE_OK`. Если список не скачался или сборка отказала, старая зона
   остаётся, а команда печатает причину.
4. Проверьте: `bash scripts/awg_dns_update.sh --status` показывает число доменов.
5. Клиентам, которые уже подключены по AmneziaWG, нужен **новый конфиг** (или новое устройство
   в боте): в старом конфиге остаётся публичный DNS.
6. Проверка с устройства через AmneziaWG: домен из списка блокировки не открывается,
   обычный сайт открывается.

Обновлять списки удобно раз в сутки (cron на сервере: `bash scripts/awg_dns_update.sh`).

## Файлы

- `deploy/awg/dns/blocklist.py`: проверка списков и сборка зоны; при ошибке старая зона остаётся.
  Пороги: от 1 000 до 1 000 000 доменов.
- `deploy/awg/agent.py`: запуск unbound, сторож резолвера, правила iptables (`start_resolver`,
  `check_resolver`, `_firewall`). Переменная `AWG_DNS_FILTER=0` выключает фильтр (только для
  отладки). `GET /healthz` включает поле `dns`.
- `deploy/awg/compose.yaml`: `mem_limit: 768m` у сервиса AWG.
- `scripts/awg_dns_update.sh`: скачивание, сборка, перечитывание резолвера (SIGHUP агенту).
- `tests/test_awg_dns.py`: проверки генератора, конфига резолвера и правил туннеля.
