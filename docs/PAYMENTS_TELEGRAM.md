# Оплата внутри Telegram: Telegram Stars

Актуально на 6 ноября 2026 года. Правила Telegram проверены по первоисточнику:
<https://core.telegram.org/bots/payments-stars>.

## Что требует Telegram

- Цифровые товары и услуги, которые продаются **внутри** бота или Mini App,
  оплачиваются только в Telegram Stars (валюта `XTR`). Подписка на подключение —
  цифровая услуга.
- Telegram может не показывать мобильным пользователям бота, который продаёт
  цифровое через сторонних провайдеров или в других валютах.
- Бот обязан отвечать на `/paysupport` (споры по оплате), `/support` и `/terms`.
  Пользователь должен принять условия до покупки.
- На `pre_checkout_query` бот отвечает за 10 секунд, иначе Telegram отменяет платёж.
- `telegram_payment_charge_id` нужно хранить: по нему делается возврат.

## Что реализовано

| Шаг | Где | Что происходит |
|---|---|---|
| Заказ | `services/billing.py` (`method="stars"`) | Заказ в БД с ценой в целых звёздах. Повторное нажатие в течение суток выставляет тот же неоплаченный заказ. |
| Счёт | `handlers/payments.py` (`send_stars_invoice`) | `sendInvoice` в чате: `currency=XTR`, без provider token, payload = номер заказа. |
| Проверка | `stars_pre_checkout` → `StarsPayments.checkout_error` | Заказ принадлежит этому пользователю, ещё не оплачен, не старше 48 ч, сумма и валюта совпадают, нет бана, оферта принята. |
| Зачисление | `stars_successful_payment` → `record_success` | ID списания Telegram привязывается к заказу (уникально), затем та же очередь активации, что у ЮKassa: срок продлевается ровно один раз. |
| Страховка | задача `stars_reconciliation` (каждые 5 мин) | `getStarTransactions`: если сообщение об оплате потерялось или обработка упала, оплаченный заказ всё равно зачисляется. |
| Возврат | `/refund <номер заказа>` (админ, при `ADMIN_TELEGRAM_READ_ONLY=false`) | `refundStarPayment`, заказ → `refunded`, оплаченный период снимается с подписки. Сообщение Telegram о возврате обрабатывается так же и не снимает период второй раз. |
| Споры | `/paysupport`, `/terms` | Вопрос по оплате уходит владельцу с пометкой; заблокированный пользователь может написать `/paysupport <текст>` одной строкой. |

Антифлуд и фильтр заблокированных пользователей не отбрасывают служебные
сообщения об оплате: деньги уже списаны, запись нужна для проверки или возврата.

## Настройки

```env
STARS_ENABLED=true
# 299 ₽ / 1.60 = 187 ⭐ (округление вверх до целой звезды)
STARS_RUB_PER_STAR=1.60
# Скрыть кнопку ЮKassa в боте; оплата на сайте (PWA) от этого не зависит
YOOKASSA_IN_BOT=false
```

Ключи для Stars не нужны: счёт выставляет сам бот. Курс — решение владельца.
Пользователь обычно покупает звёзды у Telegram дороже, чем их потом можно вывести,
поэтому при `1.60` пользователь платит примерно цену тарифа в рублях, а
владелец получает меньше. Проверьте фактическую стоимость покупки и вывода
звёзд, налоговый учёт такого дохода и доступность покупки звёзд для ваших
пользователей до массовых продаж.

## Автопродление (подписка Stars)

Включается `STARS_AUTORENEW_ENABLED=true` (по умолчанию выключено — сначала
опубликуйте оферту с п. 3.3.1). В меню оплаты Stars появляется кнопка
«🔁 Каждый месяц с автопродлением». Бот создаёт ссылку на подписку
(`createInvoiceLink`, период ровно 30 дней — другого Telegram не допускает,
цена не больше 10 000 звёзд).

- Каждое списание — отдельный платёж с уникальным ID списания Telegram;
  повторная доставка того же списания срок не увеличивает.
- `/autorenew` показывает состояние и отключает автопродление
  (`editUserStarSubscription`); оплаченный срок сохраняется.
- Обновления Telegram о подписке (`BotSubscriptionUpdated`): пользователь
  отменил, снова включил, списание не прошло — бот обновляет статус и при сбое
  списания пишет пользователю.
- Пропущенное списание находится сверкой через `getStarTransactions`.
- При возврате платежа по подписке и при списании у заблокированного
  пользователя автопродление отключается; во втором случае срок не продлевается,
  владелец получает сообщение для решения о возврате.
- Напоминание за 3 дня для пользователей с автопродлением говорит, что
  подписка продлится сама, если хватит звёзд.

## ЮKassa в Telegram (токен из @BotFather)

Владелец подключил ЮKassa через BotFather → Payments («ЮKassa: платежи»).
Это даёт **токен платежей Telegram**, а не ключи REST API. Раньше бот умел
только REST: без ключей он не создавал счёт, а уведомления ЮKassa на
`/yookassa/webhook` получали **404**. Теперь:

- с `TELEGRAM_PAYMENT_TOKEN` кнопка «💳 ЮKassa» выставляет счёт в рублях прямо
  в чате (`sendInvoice` с токеном): Telegram открывает оплату ЮKassa —
  банковская карта, ЮMoney, SberPay; списание подтверждает сам Telegram;
- вебхук, Cloudflare и RU-relay для этой схемы не нужны; если ЮKassa всё же
  шлёт уведомление, бот отвечает 200 и ничего по нему не зачисляет;
- номер платежа ЮKassa (`provider_payment_charge_id`) хранится у заказа как
  `tgyk:<номер>` — по нему платёж ищется в личном кабинете ЮKassa;
- возврат денег делается в личном кабинете ЮKassa. **Бот замечает его сам:**
  раз в 10 минут он спрашивает у ЮKassa, не вернулись ли деньги по оплаченным
  заказам (сначала часто, у старых заказов реже), и при полном возврате снимает
  оплаченный период и сообщает вам. При частичном возврате срок не меняется, бот
  только пишет вам: решение за вами (оферта возвращает неиспользованную часть).
  Работает при `ADMIN_TELEGRAM_READ_ONLY=true`. Условие: платёж виден магазину,
  чьи ключи REST (`YOOKASSA_SHOP_ID` и секрет) заданы у бота; если ЮKassa в
  Telegram подключена к другому магазину, бот пишет об этом в журнал, а срок
  снимается командой `/refund <номер заказа>` (нужен `ADMIN_TELEGRAM_READ_ONLY=false`).
  Номер заказа виден в карточке `/user <telegram_id>`;
- чеки: при `YOOKASSA_RECEIPT_MODE=self_employed` чек в «Мой налог» формирует
  ЮKassa; при `fiscal` бот запрашивает email и передаёт данные чека
  (`provider_data.receipt`);
- тестовый токен (`…:TEST:…`) бот распознаёт и предупреждает, что деньги не
  списываются.

Установка токена — на сервере, ввод скрыт, в чат и историю команд не попадает:

```bash
bash scripts/update_bot.sh --set-secret TELEGRAM_PAYMENT_TOKEN
bash scripts/update_bot.sh --payment-status
```

**Риск, о котором нужно знать.** Правила Telegram требуют Stars для цифровых
услуг внутри ботов и разрешают Telegram ограничить показ такого бота. Выбор
ЮKassa в боте — решение владельца; Stars при этом можно оставить вторым
способом (`STARS_ENABLED=true`).

Ключи REST (`SBP_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`,
`secrets/yookassa_secret_key.txt`) по-прежнему нужны только для оплаты на
сайте (PWA) вне Telegram.

## Как проверить после установки

1. `/start` → «💳 Оплата» → «⭐ Telegram Stars» → тариф → срок. Должен прийти счёт.
2. Оплатить минимальный тариф своим аккаунтом. Бот пишет «✅ Оплата получена»,
   `/status` показывает новый срок.
3. `/refund <номер заказа>` с ПК (режим управления) — звёзды возвращаются,
   срок уменьшается на оплаченный период.

Локальные тесты (`tests/test_stars.py`) покрывают эти шаги с поддельным Telegram,
но не заменяют проверку настоящего платежа.
