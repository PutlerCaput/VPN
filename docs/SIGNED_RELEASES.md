# Подписанные выпуски и защита от взлома аккаунтов

Актуально на 14 ноября 2026 года.

## От чего это защищает

До сих пор серверы ставили тот код, что лежит в GitHub: `git pull`, затем обновление. Значит,
кто получил доступ к GitHub (или к почте, через которую сбрасывается его пароль, или к сессии с
правом записи), тот мог положить свой код, и следующее обновление установило бы его на серверы,
вместе с доступом к базе клиентов и платежам.

Теперь выпуск — это коммит, который **владелец подписал своим SSH-ключом на телефоне**. Сервер
сверяет подпись с открытым ключом владельца, записанным на самом сервере, и чужое не ставит.
Ключ не покидает телефон; на сервер уходит только подпись. Взлом GitHub, почты, домена или этой
сессии с Claude не даёт поставить код без телефона владельца.

Что подпись **не** закрывает: взлом самих серверов (root на DE или RU) и потерю телефона с ключом
без пароля. Для этого ниже — список настроек.

## Как устроено

- `scripts/release_guard.sh` ставится один раз в `/usr/local/sbin/vpn-release-guard`, **вне
  репозитория**: новый код не может подменить проверку до того, как его проверили.
- Открытый ключ владельца — в `/etc/vpn-release/allowed_signers`, последняя подписанная версия — в
  `/etc/vpn-release/current`.
- Подписывается текст `vpn-release` + полный номер коммита. Подпись к одному коммиту не подходит
  к другому; откат на старый коммит или переписанная история тоже отвергаются.
- `update_bot.sh`, `update_web.sh`, `install_awg.sh`, `vless_transport.sh` и копирование кода на RU
  (`db_cutover.sh`) отказываются работать, если код на DE — не подписанный выпуск. Ручной
  `git pull` или правка файлов на сервере ловятся этим же.

## Включить (один раз)

**Termux.** Открытый ключ телефона на DE (это публичная часть, она не секретна):

```
ssh de 'cat > /root/owner_release_key.pub' < ~/.ssh/id_ed25519.pub
```

**Termux.** Поставить проверку (код на DE сейчас считается доверенным):

```
ssh de 'bash /root/vpn-src/scripts/release_guard.sh --install /root/owner_release_key.pub'
```

Ожидается `RELEASE_GUARD_INSTALLED` и строка с последним коммитом.

**Termux.** Скрипт подписи на телефон (один раз):

```
ssh de 'cat /root/vpn-src/scripts/release_sign.sh' > ~/release_sign.sh
```

## Обновление после этого

Вместо `git pull`:

```
bash ~/release_sign.sh
```

Скрипт попросит DE скачать новое, покажет номер коммита и список изменений, спросит первые 7
символов номера и только тогда подпишет. **Подписывайте, только если номер совпадает с тем, что
Claude назвал после слияния PR** (или с последним коммитом `main` на GitHub, открытым не по
ссылке из письма). Неожиданные изменения в списке — повод остановиться.

Дальше команды обновления те же (`db_cutover.sh update`, `update_bot.sh … --apply`,
`update_web.sh … --apply`). Состояние: `ssh de 'vpn-release-guard --status'`.

Если ключ на телефоне защищён паролем, `ssh-keygen` спросит его при подписи — так и должно быть.

## Список защиты аккаунтов (сделать владельцу)

Порядок важен: сначала почта, через неё восстанавливается всё остальное.

1. **Gmail**: вход по ключу доступа (passkey) или приложению-аутентификатору, не по SMS.
   Отдельная резервная почта и резервные коды — записать на бумагу. Проверить «Устройства» и
   «Сторонние приложения с доступом», лишнее удалить.
2. **GitHub**: двухфакторная защита (passkey или приложение), резервные коды на бумагу. Settings →
   SSH keys, Personal access tokens, Applications: удалить всё незнакомое и неиспользуемое.
   В репозитории: Settings → Branches → защита `main` (только через PR, без force-push).
3. **Cloudflare** (DNS домена): двухфакторная защита; API-токены — только с нужными правами,
   лишние удалить. Включить DNSSEC (DNS → Settings).
4. **Регистратор домена** `cyberdefency.com`: двухфакторная защита и **блокировка переноса**
   (Transfer lock / Registrar lock). Почта владельца домена — та, что из пункта 1.
5. **Resend**: двухфакторная защита; ключ API — только «Sending access» для одного домена
   (так и выдан).
6. **Хостеры DE и RU** (панели управления): двухфакторная защита, отдельный надёжный пароль.
   Через панель можно перезагрузить сервер в режим восстановления и обойти SSH-ключи.
7. **Telegram** владельца: облачный пароль (двухэтапная проверка). Через бота владельца идут
   уведомления и резервные копии.
8. **Телефон**: блокировка экрана, шифрование. SSH-ключ в Termux лучше защитить паролем:
   `ssh-keygen -p -f ~/.ssh/id_ed25519` (спросит новый пароль; ключ не меняется, серверы
   перенастраивать не нужно).

## Если что-то случилось

- Подозрение на взлом GitHub: ничего не подписывать; `vpn-release-guard --status` на DE покажет,
  что стоит подписанная версия. Сменить пароль и ключи GitHub, проверить список коммитов `main`.
- Потерян телефон: на DE заменить ключ в `/etc/vpn-release/allowed_signers` (зайти можно с другого
  устройства с доступом по SSH) и удалить старый ключ из `authorized_keys` на обоих серверах
  (`ssh_hardening.sh`, отчёт по ключам).
