# Проверка доработки и порядок обновления

Этот пакет изменяет исходный проект в облачном черновике. Он не подтверждает обновление действующих серверов и не содержит рабочих секретов.

## Что проверить владельцу после развёртывания проверенной сборки

1. Открыть личный чат с ботом и нажать `/start`. Прочитать действующую оферту; приветствие объясняет доступные действия.
2. Нажать «📱 Подключить устройство». Проверить свою систему: Android или Windows. Страница установки ведёт на официальный ресурс клиента, без вашей конфигурации в адресе.
3. Получить собственную конфигурацию, импортировать её в клиент и проверить обычный сайт. Отключить другой VPN на время проверки; сохранить прежний рабочий профиль.
4. Открыть `/help`. Вызвать поддержку кнопкой. Отправить описание проблемы без ключей, QR и банковских реквизитов. Проверить приход ответа в тот же чат.
5. Проверить `/cancel`: после отмены следующее обычное сообщение не должно уйти в поддержку.
6. В тестовой группе вызвать `/config`: бот не должен отправить конфигурацию. Удалять или отзывать действующие ключи ради этой проверки не требуется.
7. Проверить `/referral`, веб-кабинет и Mini App: при выключенном флаге нет ссылки для новых приглашений. Ранее начисленные дни не исчезают.
8. Убедиться, что состояние оплаты и действующие подписки не изменились от обновления. Новые тарифы и квоты этот пакет не включает.

## Для администратора

- Рабочие изменения: мастер подключения, общая маршрутизация личных чатов, безопасная доставка конфигурации, состояние поддержки, флаг новых приглашений, API и оба веб-интерфейса.
- Добавлена переменная `REFERRAL_ACQUISITION_ENABLED=false`. При отсутствии значения действует `false`. Проверить, что в окружении сервера её не переопределяет старый deployment.
- Схема БД не меняется. История платежей, существующие `referred_by`, начисленные дни и задачи применения уже возникших бонусов сохраняются.
- API `/me` дополнен `referral_enabled`; `/referral` — `enabled`. При выключенном флаге поля ссылок пустые. Серверную и клиентские части обновлять согласованно; проверить обновление PWA/service worker на устройстве.
- До замены образа сохранить текущий образ, конфигурацию и проверяемый снимок БД. Разворачивать сначала в изоляции с отдельной тестовой БД и заглушками внешних сервисов; не запускать два polling-процесса с одним рабочим токеном.
- Обновлять только сервис бота и собранные интерфейсы после проверки. Эта доработка не требует перезапуска Amnezia, Hiddify Manager, WireGuard, платёжного прокси или изменения firewall.
- Для отката использовать сохранённый образ и совместимые клиентские сборки. Из-за отсутствия миграций откат схемы БД не нужен. Публикация рекламы не является частью развёртывания.
- Файл `changes.patch` в пакете построен относительно исходников этого черновика перед доработкой. Не применять его вслепую к неизвестной версии на сервере; сначала сравнить версии. Полные изменённые файлы находятся в `changed_source/`.

## Проверки исходников

Из корня проекта, с установленными зависимостями:

```bash
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/mypy .
.venv/bin/pytest -q
.venv/bin/bandit -r . -c pyproject.toml -q
bash scripts/secret_scan.sh
npm --prefix pwa run build
npm --prefix tma run build
```

Тесты используют временные БД и локальный HTTP. Проверены правильный владелец callback, запрет выдачи в группы, обязательность активного доступа и оферты, безопасное отображение ссылки, повтор обращения после сетевой ошибки, запрет новых реферальных связей и сохранение старых. Они не заменяют реальный тест устройства, оплаты, DNS и доступности внешних серверов.
